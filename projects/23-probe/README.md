# 23-probe — 道具に訊いたことを、プロジェクトの外に憶える

dowel が道具に確かめた事実は、**利用者の cache 領域**に記録される
（ADR-0028）。プロジェクトの中ではない。

```
$XDG_CACHE_HOME/dowel/facts/v1/facts    1行1件、<鍵>\t<値>
```

```console
$ dowel cache info
directory  ./.dowel/cache/v1
format     v1
records    2
values     1885 bytes
facts      /root/.cache/dowel/facts/v1
  format   v1
  records  30
```

## 置き場所が外である理由

**事実が道具のものだから**である。同じコンパイラを使う限り答はどの木でも
同じで、`.dowel/cache/` の下に置けば木の数だけ同じ問いを繰り返す。耐久性の
階層の頂点にあるものが、最も揮発しやすい場所に住むことになってしまう。

`expect.sh` は木を2つ置いて、それを直に見ている。2つ目の木を組んでも
記録が1件も増えなければ、事実は木のものではない。

## 訊いていること

一番効くのは**ホストの三つ組**である。以前は dowel が組まれたときの OS と
構成から組み立てていた——`x86_64-unknown-linux-gnu`、常に。その機械の
コンパイラが**自分を何と呼ぶか**は訊いていなかった。

```
$ gcc -dumpmachine
x86_64-pc-linux-gnu        # そういう機械がある
```

この綴りを `--target` に渡した利用者は、cross 扱いされ、存在しえない runner
を求められる。

この検査は、自分を `x86_64-pc-linux-gnu` と名乗る shim を PATH に置いて、
両方の綴りが host として通ることを見る。そして**本当に別の機械**
（`aarch64-...`）は変わらず断られることも見る——上が「何でも通る」では
ないことの対照である。

## 鍵は道具の同一性を持つ

```
dumpmachine/path/to/mycc:197:1786490257    x86_64-pc-linux-gnu
                        ^^^ ^^^^^^^^^^
                        大きさ  更新時刻
```

無効化の機構は意図的に無い。**道具を差し替えれば鍵が変わり、古い事実は
二度と引かれない。** 上書きではなく届かなくなるので、誤った事実が生き残る
ことも無い。集めるのは `dowel cache gc` である。

`expect.sh` は shim を書き換えてから組み直し、記録が1件増えること
（＝訊き直したこと）と、古い記録が残っていることの両方を見ている。

## 消しても安全

どちらも cache である。手で消して壊れるなら、それは cache ではない。
消してから組み直し、記録が書き戻され、同じ答に至ることを見ている。

`cache info` と `cache gc` はマニフェストを読まない。壊れた木でも掃除できな
ければ意味が無いためで、`expect.sh` はマニフェストを壊してから `cache info`
を打っている。

## 記録の場所は検査が握る

`XDG_CACHE_HOME` を木の中へ向けてある。本物の利用者 cache を触ると、検査が
手元の履歴に依存し、走らせた順で結果が変わる。
