# 16-migrate — 既存のビルドからの移行

`dowel migrate` が受け持つのは片道の作業である。下書きが黙って何かを落として
も、利用者は組み上がったものを見て「移った」と読む。落ちたものは、そのプロ
ジェクトが動かなくなったときに初めて分かる。

固定するのは2つ。

1. **何が写り、何が写らないと明示されるか** — `migrate import`
2. **写した結果が元と同じ翻訳になるか** — `migrate verify`

2 は 1 の答合わせである。`import` 自身が出力の最後で `verify` を指しており、
この2つは1つの手順として設計されている。したがって「`import` の出した下書きを
そのまま `verify` に掛けると何も報せずに終わる」ことが、この機能全体の
いちばん外側の期待値になる。現状これは通らない（[F-017](../../docs/10-findings.md#f-017)）。

## 中身

| | |
|---|---|
| `cmake-project/` | 移行元。静的ライブラリ1つと実行ファイル2つ。end-to-end に使う |
| `cmake-shapes/` | 対象の種類だけを見る移行元。OBJECT / SHARED / INTERFACE / 系のライブラリ |
| [`normalize/`](normalize/) | `verify` の正規化を見る手書きのパッケージ |
| [`normalize/refs/`](normalize/refs/) | 参照 compile_commands.json の雛形。`@ROOT@` を差し替えて使う |

`cmake-project/` と `cmake-shapes/` は dowel のパッケージではない。マニフェスト
は `expect.sh` が `migrate import` に書かせる。`import` は上書きを拒むため、
構成ごとに別の複製へ取り込む（`from-debug/` と `from-release/`）。

## 構成のフラグを揃えてあること

`cmake-project/CMakeLists.txt` は `CMAKE_C_FLAGS_DEBUG` を `-g -O0`、
`CMAKE_C_FLAGS_RELEASE` を `-O2 -DNDEBUG` にしている。dowel が構成ごとに
暗黙に足すものと同じである。

揃えないと、全ソースにこの差が出る。そうなると `verify` の報告が
「移行の誤り」を言っているのか「構成の食い違い」を言っているのかを
読み分けられない。ここでの関心は前者だけである。

## 何をどう観測しているか

| 見たいこと | 見方 |
|---|---|
| 下書きに写ったもの | 生成された `dowel.build` の中身 |
| 写らなかったものが明示されるか | 下書きの中の注記（`was a SHARED_LIBRARY`） |
| 下書きが本当に使えるか | `check` → `build` → 成果物を走らせる |
| 翻訳された構成 | `src/report.c` に `NDEBUG` と `__OPTIMIZE__` を名乗らせる |
| 正規化の範囲 | 手書きの参照を `verify` に掛け、4つのバケツの数で見る |

最適化されたかどうかを機械語の量で測ると、測っているのがコンパイラの世代なのか
dowel の渡した引数なのかが分からなくなる。`__OPTIMIZE__` は gcc と clang の
双方が最適化水準 0 でないときにのみ定義するため、「`-O0` が `-O2` に勝ったか」
をそのまま読める（[docs/00-design.md](../../docs/00-design.md) 6節）。

## 正規化で等価とみなすもの

`verify` が比べるのは「翻訳を決めるもの」だけである。

| 差にならないもの | 理由 |
|---|---|
| コンパイラの名前 | 起動する道具の話であり、翻訳の内容ではない |
| `-c` / `-o` | どこへ出すかの話 |
| `-MD` `-MMD` `-MP` `-MF` | 依存ファイルの生成。目的ファイルは変わらない |
| `-DA` / `-D A=1` / `-DA=1` | 同じ定義の3通りの綴り |
| 相対と絶対の `-I` | 各項目の `directory` を基に解決する |
| 引数の順序 | 多重集合として比べる |

これらだけを検査すると「何を渡されても等価と答える実装」も通るため、
本物の差が残ることを `differing.json.in` で必ず確かめる。

## バケツと終了状態

| バケツ | 意味 | 終了状態 |
|---|---|---|
| `equivalent` | 同じ翻訳 | |
| `differing` | 引数が違う | **非0** |
| `not ported` | 参照にあり dowel に無い | 0 |
| `only in dowel` | dowel にあり参照に無い | 0 |

移行の途中では、まだ移していないファイルも dowel 側にしかないテストも普通に
居る。落とすのは「移したつもりで違うものを作っている」場合だけである。
