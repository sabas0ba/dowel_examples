# 27-generate — ソースを作る段をビルドの中へ入れる

目標は自分のソースの作られ方を宣言できる
（[ADR-0054](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0054-generated-sources.md)）。
backend が綴れない命令は、書き換えられずに拒まれる
（[ADR-0058](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0058-a-command-a-backend-cannot-spell.md)）。

解析器を `bison` から、走査器を `flex` から、型を `protoc` から、表を script
から。dowel は既に在るソースしか翻訳できず、**作られる**ソースを持つ
プロジェクトはそれをマニフェストに書けなかった。唯一の組み方は「先に手で
生成器を走らせる」であり、そうすると生成物は checked-in のソースに見え、
その鮮度はビルドの外へ出る。

```toml
[bin.calc.generate]
parser = { command = "bison", args = ["-d", "-o", "parser.c"],
           inputs = [file("src/parser.y")], outputs = ["parser.c", "parser.h"] }
```

## 走る場所が、綴らねばならないことを決める

生成器がビルドディレクトリで走るなら、`parser.c` を作る目標が2つあれば
互いを踏む。そして `outputs` は**マニフェストからは組み立てられない path**
で綴ることになる——ビルドディレクトリの名前は構成に依るためである。

生成ごとに `<build>/generated/<パッケージ>/<目標>/<名前>/` を与え、
**その中で走らせる**。綴るのは相対名だけで足り、`-o parser.c` がそのままの
意味になり、2つの生成は踏み合わない。

## 何を確かめるか

| 見るもの | 期待 |
|---|---|
| 段であること | `GEN` として現れ、出てきた `.c` が**宣言した目標**へ翻訳される |
| 走る場所 | アクショングラフの `cwd` が生成の置き場そのもの |
| 命令の形 | `<command> <args...> <inputs...>`。`file()` は絶対 path へ開く |
| 見出しの経路 | 置き場が `-I` に載る。`public = true` で使う側へ伝わり、**書かなければ伝わらない** |
| 鮮度 | `inputs` が変われば作り直し、出てきたソースも使う側も翻訳し直す |
| 名前の衝突 | 同じ名前の生成を2つの目標に置いても、書く先が違う |

### 順序が付くことは、通ったことでは言えない

ADR-0054 が測った箇所である。ninja は plan の `deps` を読まず、
`build <出力>: <規則> <入力>` の file の関係だけで順序を決める。生成した
見出しをどの翻訳も入力に挙げていなければ、**順序は付かない**——翻訳が先に
走り、生成は一度も走らない。

だから生成した出力は、届く範囲の**全ての**翻訳の入力になる。見出しを
取り込む翻訳だけではない。どの翻訳がどの見出しを読むかは depfile の答で
あり、それが出るのは最初の翻訳が通ったあとで、順序を決めるには遅すぎる。

検査は入力の側（何本の翻訳が生成物を入力に持つか）と、結果の側（空から
3つの backend で組み直す）の両方を見る。**一度通るだけでは足りない。**
順序が付いていない木は、付いていないまま通ることがある。

### make が取れない形

make は1つの段につき1つの出力しか取れない。`bison -d` はまさに `.c` と
`.h` を1度に書くので、避けて通れる話ではない。ここでは木を1出力ずつに
分けて3つの backend すべてで組み、多出力の形は別に組み立てて**拒むこと**を
見る。

## 綴れない命令（ADR-0058）

```toml
g = { command = "sh", args = ["-c", "printf '#define A 1\nB' > cfg.h"], outputs = ["cfg.h"] }
```

| backend | かつて起きたこと |
|---|---|
| `direct` | 正しい。`argv` を `exec` へ渡し、shell の行を組まない |
| `ninja` | **成功し、違うものを組んだ**。改行を空白へ潰していた |
| `make` | `Makefile:13: *** missing separator`。dowel が生成したファイルの行番号 |

いまはどちらも拒む。**書き換えない。** 診断は直し方を名指す——`\n` は
マニフェストの escape なので `printf` が受け取る前に改行そのものへ変わって
おり、`\\n` と綴れば3つの backend すべてで同じファイルが書かれる。

検査は、拒むことに加えて**ビルドファイルを1バイトも書かないこと**を見る。
半端に書かれたビルドファイルは、前のものを壊したまま残る。
