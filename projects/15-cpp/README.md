# 15-cpp — C++

かつて C++ のソースは黙って `cc` に渡され、リンクで
`undefined reference to std::...` になっていた
（[F-008](../../docs/10-findings.md#f-008)）。報告時に挙げた2案のうち、
まず「診断で拒む」（`unsupported-language`）で決着し、その後
**C++ を組めるようにする**側が入った。

ここで受け持つのは、その C++ 対応が「拡張子で選ぶ」だけで終わっていないか
である。**難しいのは翻訳ではなくリンクの側にある。**

## 何を固定するか

### 1. コンパイラはソースごとに拡張子で選ばれる

C++ は `.cc` `.cp` `.cpp` `.cxx` `.c++` `.CPP` `.C`。`exts/` に1拡張子1本ずつ
置いて、アクショングラフの `argv[0]` を見る。

`.C` だけが大文字1文字であり、**`.c` と1文字違いで意味が反転する**。
取り違えると、C として書かれたものが C++ として翻訳されるか、その逆になる。

なお、大文字小文字だけが違う名前は大小を区別しないファイルシステムで衝突する
ため、ファイル名の語幹は拡張子ごとに変えてある。

### 2. リンクは依存の閉包で決まる

**これが F-008 の失敗様式そのものである。**

`capp/` はソースが `.c` だけの実行ファイルだが、C++ のライブラリに依存する。
拡張子だけを見ていると C の driver でリンクしてしまい、標準ライブラリが
繋がらない。

```
cc    src/main.c        ← 自分のソースは C の driver
c++   src/lib.cpp       ← 依存の側は C++ の driver
link  c++               ← リンクは C++ の driver
```

引数の形だけでは足りないので、**実際に繋がっていること**も見る。純 C の
テストから `std::string` を使う関数を呼び、通ることを確かめる。C++ 実行時が
欠けていればリンクで落ちる。

### 3. 1つのターゲットに混在できる

`mixed/` は同じターゲットに `.c` と `.cpp` を持つ。それぞれが正しい driver へ
渡り、リンクは C++ で行われる。

**C の側で確かめる。** C の翻訳単位で `__cplusplus` が定義されていたら、
拡張子による選択が効いていない。成果物自身に答えさせ、期待値をハーネスと
二重に持たない。

### 4. `cxx` の宣言と `tc.cxx`

既定は `c++`。`[toolchain] cxx` で上書きでき、それが `argv[0]` に届く。
`tc.cxx` は構成の語彙に入っており、宣言によって具体化を変えられる。

### 5. 要求されるのは要るときだけ

> C++ のツールチェーンは C++ のソースがあるときだけ要求され、そのときだけ探される

C しか書いていない利用者に C++ コンパイラの用意を強いるなら、それは
**C 専用の構成が組めない**ということである。壊れた `cxx` を宣言したまま、
C++ のソースがある場合は `missing-toolchain` で拒み、無い場合は素通りする
ことを対で見る。

## この形で確かめられないもの

言語ごとのフラグ（`cxx_flags`、C++ 標準の選択）。本体の実装状況では未決で
あり、今日は `flags` が C と C++ の双方の翻訳単位に適用される。決まった段で
足す。

`toolchain-mismatch`（依存パッケージが別のツールチェーンを宣言した場合の
警告）。ABI 検査の側の話であり、`04-diagnostics` の併合の層に近い。
