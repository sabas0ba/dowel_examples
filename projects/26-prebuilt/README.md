# 26-prebuilt — 既に在るライブラリを依存として書く

`lib` は `sources` の代わりに `prebuilt` を宣言できる
（[ADR-0049](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0049-prebuilt-libraries.md)）。
ABI 札は成分の集合になった
（[ADR-0042](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0042-abi-label-components.md)）。

C や C++ のプログラムは、dowel が組まなかったものを繋ぐことが多い——Rust の
`staticlib`、Zig の `build-lib`、Go の `c-archive`、vendor の SDK。
これまでの綴りは、使う側それぞれに書く2つの旗だった。

```toml
link_flags = ["-L", dir("target/release"), "-lengine"]
```

それは依存ではない。**見出しの経路を伝えず、ABI 札を持たず、`dowel why` に
現れず、他の全ての検査に参加しない。** ビルドの中心にあるファイルが、dowel が
意味を解さないまま通す2つの旗で書かれている。

記述されているものは目標そのものである。面を持ち、要求を持ち、使う側が依存
する。**欠けているのはソースだけ**である。

## 木の形

`vendor/` に Makefile を置いてある。ADR-0049 の想定する相手（cargo / zig /
go / vendor の SDK）の代わりであり、**dowel はこれを走らせない**——走らせて
しまえば汎用のビルドシステムになる（ADR-0001）。

## 何を確かめるか

| 見るもの | 期待 |
|---|---|
| 普通の目標であること | `public` が伝わり、`dowel why` が辿り、翻訳も書庫化も起きない |
| 無い場合 | `missing-prebuilt`。位置つき、探した path つき、**誰が作るはずだったか**つき |
| 更新 | 書庫を差し替えれば繋ぎ直す。他のあらゆる入力と同じ同一性で見る |
| `sources` と併記 | `prebuilt-with-sources`。ここで組むのか他所で組まれたのか、両方は答えが無い |
| `bin` に書く | `prebuilt-not-a-library`。繋ぐ相手であって走らせる物ではない |

## ABI 札が初めて確かめる価値のある辺を得た

「1つのビルドの中では道具立ても構成も一様である」（ADR-0031）ため、**手元で
組んだもの同士**の札はいつも一致し、比較は空虚だった。片側が他所で組まれて
いる場合に初めて、札が食い違いうる。

musl で組まれた書庫を gnu のビルドへ繋ぐと、**結合の前に**拒まれる。
診断は要求と実際の三つ組の両方を述べ、さらに「結合は通ってしまい、壊れるのは
実行時である」——だから計画の段で止める価値がある——ことまで言う。

相手が名指さない成分は制約ではない。粗い宣言は少ししか縛らず、細かい宣言は
多く縛り、**どちらも相手の決めたことを知らずに合成できる**。粒度の板挟みに
「選ばない」で答えたのが ADR-0042 である。

## 残っているもの

札を受け取る目標の数だけ同じ診断が出る。文面に目標の名前が入っていないため、
読む側には**同じ誤りの写し**に見える（[F-064](../../docs/10-findings.md#f-064)）。
