# 08-lsp — 言語サーバ

`dowel lsp` は標準入出力で LSP を話す。エディタが起動主体であり、
[ADR-0002](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0002-no-daemon.md)
が退けた常駐デーモンとは区別される。

本体の `dowel-lsp` は自分自身を内側から検査している。ここで受け持つのは
そこから見えない側、すなわち **CLI と言語サーバが同じ本文に同じ答を返すか**
である。

両者は別の入口だが、利用者にとっては同じ道具である。片方が黙っている誤りは、
その入口を使う利用者にとって存在しない誤りになる。しかも編集中の利用者は
エディタの方を信じるため、黙っている側が実質的な仕様になる。

## 構成

対象は [`subject/`](subject/) ひとつ。`checks.py` がその `dowel.build` を
**エディタの緩衝として** `didOpen` / `didChange` で差し替える。ディスク側は
常に正しい形のままである。

| | |
|---|---|
| [`checks.py`](checks.py) | 検査の本体。`status \| desc \| 所見` を1行1検査で書く |
| [`../../lib/lsp_client.py`](../../lib/lsp_client.py) | 枠付けと JSON-RPC。本体と同じく自前に持つ |
| [`expect.sh`](expect.sh) | 行を読んでハーネスに記録するだけ |

シェルから JSON-RPC を話すのは無理があるため、この段だけ Python で書く。
ハーネスとの境界は他のプロジェクトと同じ「1検査1行」に揃えてある。

## 何を固定するか

### 1. 手続きと文書の出入り

`initialize` の応答、`didOpen` / `didChange` / `didSave` / `didClose` に
応じた `publishDiagnostics`、`shutdown` / `exit` での終了。

**誤りが無いときも通知が来ること**を見る。黙っているのと「誤りが無い」のは
エディタから区別できず、前者なら前回の誤りが画面に残り続ける。

### 2. 壊れた JSON-RPC で接続が落ちないこと

「読めない本文は捨てて次を読み、1件の不正で接続を落とさない」。
エディタと言語サーバの間にはこちらが書いていない実装が挟まるため、
1件の不正で落ちると利用者には言語サーバが不安定に見える。

枠付けが正しく本文だけが読めないものは、**復帰まで**見る。枠付けそのものが
壊れているもの（`Content-Length` が無い、実体より長い）は、本文の終わりが
決まらないため捨てて次へ進むことが原理的にできない。ここは生存だけを見る。

### 3. 桁が UTF-16 単位であること

LSP の桁は UTF-16 単位である。バイト数や符号位置数と一致してしまう入力
だけを見ていると、取り違えても気づけない。

| 文字 | バイト | 符号位置 | UTF-16 |
|---|---|---|---|
| `a` | 1 | 1 | 1 |
| `é` | 2 | 1 | 1 |
| `日` | 3 | 1 | 1 |
| `💩` | 4 | 1 | **2** |

**星界面の文字が初めて3つの数え方を分ける。** 出す側（診断の範囲）と
受ける側（ホバーの位置）の両方を、この4種で見る。

### 4. CLI との一致

同じ本文を `dowel check --message-format=json` にも掛けて、出る安定コードを
突き合わせる。現在 6 件が食い違う（[F-012](../../docs/10-findings.md#f-012)）。

各件には `dowel check still reports <code>` を対にしてある。CLI 側が
出さなくなった場合に、比較の前提が崩れたことが分かる。片側だけを見ていると、
一致していないのか、そもそも誤りでなくなったのかが区別できない。

### 5. ホバー

ホバーはスキーマそのものを説明にする。プロパティの型と併合規則、
表の見出しの各段、組み込み関数の署名、構成キーの値域。

**誤りを含むファイルでも説明が出ること**を見る。編集中のマニフェストは
常にどこかが壊れているため、ここが働かないとホバーは「直し終わってから
使うもの」になり、修復の役に立たない。

壊す場所は後ろの行にする。閉じていない呼び出しは以降の行を引数として
飲み込むため、その内側の語は語として残らない。これは復帰の仕方であって
説明の不在ではない。

未知のプロパティにホバーが無いことも見る。スキーマを引けている証拠であり、
同じ判定が診断として出ていないこと（F-012）と対になる。

### 6. 頑健性

[07-robustness](../07-robustness/) と同じ性質を、言語サーバの入口から見る。

深い入れ子で言語サーバは落ちる（[F-010](../../docs/10-findings.md#f-010)）。
CLI では利用者がシェルに戻るだけだが、ここでは**エディタとの接続が切れる**。
入力は編集中の本文であり、括弧が閉じていない状態は編集のたびに必ず通る。

## この形で確かめられないもの

VS Code 拡張そのもの（`editors/vscode/`）。本体が実物の VS Code で回す
E2E を持っており、そちらと重ねる意味は薄い。ここで見るのは拡張が話す相手の側である。

ファイルを跨ぐ診断。`dowel_lsp::UNSUPPORTED` に理由とともに列挙されており、
出ないことが宣言されている。宣言されているものを検査しても、
宣言と実装の一致しか見ないことになる。
