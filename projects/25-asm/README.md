# 25-asm — アセンブリを第3の言語として扱う

拡張子で言語を選ぶ規則は「C++ の綴りなら C++、**それ以外は C**」だった。
`.s` と `.S` は第3の言語になった
（[ADR-0048](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0048-assembly.md)）。

手書きのアセンブリは `cc` に渡せば実際に組み上がるので、**既に動いているように
見えていた**。出てきたものを測ると3つ違っていた。

| 何が起きていたか | なぜ気づかれないか |
|---|---|
| `-std=c17` と `-Wall` がアセンブラに渡っていた | gcc が黙って受ける |
| `.note.GNU-stack` が付かず、結合器が実行可能スタックを警告 | 警告であって誤りではない |
| `.s` に `-MD -MF` を渡し、書かれない依存ファイルを宣言 | 何も確かめていなかった |

どれも「利用者の代わりにビルドシステムが正しくやる」種類のものである。
だから検査も、宣言ではなく**出てきた引数**と**出てきた成果物**を見る。

## 何を確かめるか

### 旗の行き先

1つの目標に C・`.s`・`.S` を同居させ、`flags` / `c_flags` / `asm_flags` を
それぞれ宣言して、**アクショングラフに出てきた引数**で仕分けを読む。

| 宣言 | C へ | アセンブリへ |
|---|---|---|
| `flags` | ○ | ○ |
| `c_flags` / `c_std` | ○ | × |
| `asm_flags` | × | ○ |

### dowel が自分で足すもの

`-Wa,--noexecstack` は共有ライブラリの `-fPIC` と同じ種類の引数である——
出てくるものの正しさがそれに依り、他に足す者がいない。

引数に在ることだけでは足りない。**出てきた実行ファイル**の `GNU_STACK` が
`RW` であること（`E` が立っていないこと）まで読む。そして利用者が覆せるよう、
dowel の足すものが先に来ることも見る。

### 依存ファイル

`.S` は前処理を通るので見出しの依存を持ち、`.s` は持たない。**書かれない
依存ファイルを宣言することは、現れない出力を宣言すること**であり、増分
ビルドが収束しなくなる形である。

宣言の有無だけでなく、取り込んだ見出しを書き換えて組み直されることと、
**3つの backend すべてで2度目に何も残らないこと**を見る。「依存ファイルは無い」の
綴りは backend ごとに違う——ninja では変数を束ねないと自分自身に解決して循環になる。

## 綴りは閉じている（[ADR-0051](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0051-source-language-is-closed.md)）

「それ以外は C」という落とし前は、未知の綴りについての判断ではなく、`.c` に
ついての判断を**全部を飲み込む書き方でした**ものだった。払っていたものは
[F-063](../../docs/10-findings.md#f-063) に書いてある——警告つきの成功、
終了状態 0、目的ファイル無し、そして結合器の言葉で返る失敗。

いまは `unknown-source-language` が、**ソースを宣言したところ**を指して断る。
拡張子の無いソースも同じである。前処理を通した C（`.i`）は受ける。

### 出したはずのものが無い実行は失敗

拡張子の検査はマニフェストから見えるものしか覆えない。宣言された道具が黙って
何もしない場合の網は2枚ある。検査もその2つを別々に見る。

| どこ | 何を出せるか |
|---|---|
| direct | 段ごとに出力を見る。**成功した命令とその stderr** まで出せる |
| ninja / make | どちらも出力が無いことでは落ちない。網はビルドの**あと**に、`built:` が指す先を見る |

## 自前の assembler（[ADR-0050](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0050-separate-assembler.md)）

`nasm/` が `asm = "nasm"` を宣言する。暗号や符号のライブラリは x86 向けに
NASM のソースを配る——生成器が Unix の triple へは gas を、Windows へは NASM を
吐くためで、Windows の側は C の駆動器が聞いたこともない道具を要る。

dowel が渡すのは**入力と出力と `asm_flags` だけ**である。翻訳の行の残りは
C の駆動器のために綴られたものであり、assembler はそれではない。検査は
出てきた命令行でそれを読む——`-f elf64` は届き、`-g -O0` も `flags` も届かない。

実行可能スタックの主張は、最後に dowel が言える場所へ移る。`-Wa,--noexecstack`
は C の駆動器の綴りなので渡せず、結合の側で `-z noexecstack` になる。

## 残っているもの

`missing-assembler` の下線が、ソースではなく `[bin.<名前>]` の行に付く
（[F-067](../../docs/10-findings.md#f-067)）。文言は「declared as a source
here」のままなので、指している先と言っていることが食い違っている。
隣の `unknown-source-language` は正しく指すので、対照はその並びに在る。
