# 25-asm — アセンブリを第3の言語として扱う

拡張子で言語を選ぶ規則は「C++ の綴りなら C++、**それ以外は C**」だった。
`.s` と `.S` は第3の言語になった
（[ADR-0048](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0048-assembly.md)）。

手書きのアセンブリは `cc` に渡せば実際に組み上がるので、**既に動いているように
見えていた**。出てきたものを測ると3つ違っていた。

| 何が起きていたか | なぜ気づかれないか |
|---|---|
| `-std=c17` と `-Wall` がアセンブラに渡っていた | gcc が黙って受ける |
| `.note.GNU-stack` が付かず、結合器が実行可能スタックを警告 | 警告であって誤りではない |
| `.s` に `-MD -MF` を渡し、書かれない依存ファイルを宣言 | 何も確かめていなかった |

どれも「利用者の代わりにビルドシステムが正しくやる」種類のものである。
だから検査も、宣言ではなく**出てきた引数**と**出てきた成果物**を見る。

## 何を確かめるか

### 旗の行き先

1つの目標に C・`.s`・`.S` を同居させ、`flags` / `c_flags` / `asm_flags` を
それぞれ宣言して、**アクショングラフに出てきた引数**で仕分けを読む。

| 宣言 | C へ | アセンブリへ |
|---|---|---|
| `flags` | ○ | ○ |
| `c_flags` / `c_std` | ○ | × |
| `asm_flags` | × | ○ |

### dowel が自分で足すもの

`-Wa,--noexecstack` は共有ライブラリの `-fPIC` と同じ種類の引数である——
出てくるものの正しさがそれに依り、他に足す者がいない。

引数に在ることだけでは足りない。**出てきた実行ファイル**の `GNU_STACK` が
`RW` であること（`E` が立っていないこと）まで読む。そして利用者が覆せるよう、
dowel の足すものが先に来ることも見る。

### 依存ファイル

`.S` は前処理を通るので見出しの依存を持ち、`.s` は持たない。**書かれない
依存ファイルを宣言することは、現れない出力を宣言すること**であり、増分
ビルドが収束しなくなる形である。

宣言の有無だけでなく、取り込んだ見出しを書き換えて組み直されることと、
**3つの背骨すべてで2度目に何も残らないこと**を見る。「依存ファイルは無い」の
綴りは背骨ごとに違う——ninja では変数を束ねないと自分自身に解決して循環になる。

## 残っているもの

`.asm` はアセンブリとして認識しない、という決定がある（MASM / NASM の綴りで
あり、C の駆動器が受け付けないため）。ところが認識されない綴りは C の駆動器へ
行き、`cc -c` はそれを**結合器への入力**とみなして警告を出し、**終了状態 0 で
目的ファイルを書かずに返る**。dowel は現れない出力を宣言したまま先へ進み、
結合が path で落ちる（[F-063](../../docs/10-findings.md#f-063)）。

`check` は通り、収束もしない。ADR-0048 自身が「現れない出力を宣言することは
増分ビルドが収束しなくなる形」と書いている、その形がここに残っている。
