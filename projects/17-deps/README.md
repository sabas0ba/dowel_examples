# 17-deps — システムパッケージへの依存と `dowel.lock`

`dowel.toml` の依存には3つの形がある。`path` はローカルの内容そのもの、
`git` は rev が内容を固定する。残る `version = "..."` は
[ADR-0015](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0015-version-deps-pkgconfig.md)
でシステムの pkg-config への委譲として実装された。

前の2つと決定的に違うのは、**何が来るかを環境が決める**ことである。だから
記録（`dowel.lock`）が要る。ただし記録が約束するのは復元ではない。システム
パッケージは取得できないため、約束できるのは「前回と違うものを黙って使わない」
ことだけである。

固定するのは3つ。

1. 解決の結果が翻訳とリンクへ正しく届くか
2. 解決できないときに、直し方の分かる形で拒むか
3. 環境が変わったときに、黙って別のものを使わないか

## 相手にするシステム

`system/` に置いた `.pc` である。**実際のシステムには触れない。**

```
system/
  demokit.pc          Version 2.4.0、Cflags と Libs（-lm）を持つ
  quiet.pc            Version 1.0.0、Cflags のみ
  include/
```

機械に入っているパッケージを相手にすると、検査が落ちたときに直すのが dowel
なのか機械なのかを判断できなくなる（[docs/00-design.md](../../docs/00-design.md) 6節）。
`.pc` を持ち込めば、版も、フラグの中身も、こちらが決められる。

`.pc` の中では `${pcfiledir}` を使う。`.pc` 自身の置かれた場所に展開される
ため、複製先の絶対パスを知らずに済み、雛形の差し替えが要らない。

## 中身

| | |
|---|---|
| `app/` | 単一パッケージ。解決、伝播、版の下限、`dowel.lock` |
| `chain/` | `top`（bin）→ `mid`（lib）→ `demokit`。`private` と `public` で割れる |
| `gated/` | `optional` な `version` 依存。無効なときは解決すらされないこと |

## 版は下限である

宣言した版は最小値であり、比較は pkg-config 自身（`--atleast-version`）が行う。
dowel は大小の判定を持たない。したがって検査するのは「dowel の比較が正しいか」
ではなく、**委譲が正しく行われているか**である。

`system/demokit.pc` は 2.4.0 なので、1.0 と 2.0 と 2.4.0 は満たされ、9.9 は
`unsatisfied-dependency` になる。

## `dowel.lock`

| 状況 | 起きること |
|---|---|
| 記録が無い | 解決結果を追記する |
| 記録と一致 | 何もしない。**1バイトも書き換えない** |
| 記録と食い違う | `lockfile-drift` を警告し、**書き換えない** |

一致するたびに書き換わると、版管理の差分が「解決したこと」ではなく「走らせた
こと」を表すようになる。食い違ったときに書き換えると、記録の意味が無くなる。
受け入れる操作は当該項目（またはファイル）を消すことであり、警告自身がそう
言う。

`dowel.lock` はワークスペースの根に置かれる。`chain/` では依存を宣言して
いるのは `mid` だが、記録は呼び出しの根である `top` 側に出る。

## リンクの閉包（[F-018](../../docs/10-findings.md#f-018)）

静的な書庫は自分のリンク要件を運べない。`lib` が `private` に持つリンク要件も、
依存元の最終リンクへ届かなければ解けない。

`chain/` は同じ木を2通りに宣言して両側を見る。

| `mid` の宣言 | `top` のリンク | `top` の翻訳に届くもの |
|---|---|---|
| `private` | **失敗**（`undefined reference`） | 何も届かない（正しい） |
| `public` | 成功 | `-I.../include` `-DDEMOKIT=1`（漏れている） |

「ヘッダを漏らさない」と「リンクできる」を同時に選べない。書庫の側は既に
`private` を跨いで閉包を辿っている（`libdemokit.a` は `top` のリンク行に
現れる）。届いていないのは `link_flags` だけである。

`private` のまま漏れないことを見る検査は通常の検査として置いてある。
`xfail` の2件と**同時に**通ることが期待値であり、片方だけを満たす直し方
（全部 public 扱いにする）を通さないための組である。

## 言語サーバとの境界

`version` 依存の解決とロックの突き合わせは言語サーバでは行われない。会期は
読むだけであり、外部のプロセスを起こさないためである（ADR-0015）。
その検査は [`08-lsp`](../08-lsp/) の `unsupported_boundary` に置いてある。
エディタで開いただけで `dowel.lock` に差分が出ないことも、そこで見る。
