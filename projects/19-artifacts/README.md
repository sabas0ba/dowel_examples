# 19-artifacts — 成果物から別の成果物を作る

組み込みでは、リンクの後に必ず1段ある。ELF を書き込み用の生イメージや
Intel HEX に変え、あるいは剥いだ複製を作る。

```toml
[bin.image.artifacts]
bin = { tool = "objcopy", args = ["-O", "binary"] }
hex = { tool = "objcopy", args = ["-O", "ihex"] }
```

この1段をビルドグラフの**内側**に置くのが `[<kind>.<name>.artifacts]` である
（[dowel#60](https://github.com/sabas0ba/dowel/issues/60)）。

## 内側に置くことで何が変わるか

外で `objcopy` を叩いても同じファイルは作れる。違いは3つある。

| | 外で叩く | グラフに乗せる |
|---|---|---|
| 作り忘れ | 起きる | `dowel build` が作る |
| 増分 | 毎回走る | 元が変わらなければ走らない |
| クロス | ホストの objcopy が走る | 宣言した道具が選ばれる |

3つ目がこの機能の要である。別アーキテクチャの ELF をホストの objcopy が
扱うと、黙って誤ったイメージが出うる。[`18-tools`](../18-tools/) が見る
「道具の宣言」の上に、この層が積み上がっている。

## 中身

| | |
|---|---|
| `firmware/` | 生イメージと HEX。命令の形、誤った宣言、増分 |
| `cross/` | 三つ揃えた宣言（`c` / `ar` / `objcopy`）と、その下での変換 |
| `library/` | `lib` に付けた派生（[F-022](../../docs/10-findings.md#f-022)） |

## 何をどう観測しているか

変換が**本当に走ったか**は、出来上がったファイルの中身で見る。

- 生イメージの先頭に ELF の魔法数が無い（`objcopy -O binary` は節の中身だけを出す）
- 生イメージにソースへ埋めた印（`DOWEL-ARTIFACT-MARKER`）が入っている
- HEX の各行が `:` で始まる

ファイルが在るだけでは、空のファイルを置いた実装も通る。

命令の形も固定する。**入力と出力はマニフェストに書かない。**

```
objcopy -O binary <ビルドディレクトリ>/bin/image <ビルドディレクトリ>/bin/image.bin
```

実装が末尾に付ける（`[runner]` の転送と同じ規約、ADR-0008）。書けてしまうと、
書いた道と実装が付ける道のどちらが効くのかが利用者に分からなくなる。

`cross/dowel.build` は `aarch64` という語を1文字も含まない。道具の名前だけを
書き、具体的なコマンドは `[toolchain.<triple>]` から来る。その不在も検査に
してある。

## 要るときだけ

`objcopy` が探されるのは、それを使う宣言があるときだけである。派生を持たない
木は壊れた `objcopy` の宣言があっても組める。`ar` が書庫を作るときだけ要るのと
同じ理屈である。

## ライブラリの派生（[F-022](../../docs/10-findings.md#f-022)）

`lib` に付けた派生は、そのライブラリを使う `bin` を1つ足すと作られなくなる。
`artifacts` の宣言は何も変えていない。

| 構成 | `dowel build` が作るもの |
|---|---|
| ライブラリだけ | `libpart.a` `libpart.stripped` |
| そこに依存する `bin` を足す | **`libpart.a` のみ** |
| `dowel build part` と名指し | `libpart.a` `libpart.stripped` |

`libpart.a` は依存として作られるのに、その隣の `libpart.stripped` は作られない。
**派生が作られるかどうかが、そのターゲット自身の宣言ではなく、別のターゲットが
自分に依存しているかどうかで決まっている。**

組み込みでは、ライブラリ側の objcopy 済みの形が納品物になることがある。
それが実行ファイルを1つ足した拍子に、診断も警告も無く消える。

## まだ無いもの

ファイルを作らない道具（`size` / `nm` / `objdump`）は宣言できない。出力が
成果物ではなく報告であるため、置き場所が別に要る
（[F-020](../../docs/10-findings.md#f-020)、[`18-tools`](../18-tools/) が見る）。

`size` は特に、flash / RAM の予算を超えたらビルドを落とすという使い方があり、
「作る」のではなく「判定する」側の機構になる。
