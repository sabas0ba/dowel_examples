# 29-tool-identity — 道具の同一性を入力として記録する

道具の同一性はファイルに書かれ、そのファイルはその道具を走らせる全ての
アクションの入力である
（[ADR-0055](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0055-tool-identity-in-freshness.md)）。

dowel は2つのものから何が古いかを決めていた——アクションが読むファイルと、
走らせる命令行。どちらも**プログラムが変わったこと**に気づかない。命令行は
`cc` と書いてある。入れ替えたあとも `cc` と書いてある。

```console
$ dowel build                  # mycc は `exec cc "$@"`
[2/2] LINK bin/app
$ # mycc を `exec cc -DPATCHED "$@"` へ書き換える
$ dowel build --backend=direct --log-level=debug
      5.0ms debug direct       ran 0 steps, skipped 2 already up to date
```

古いコンパイラで作った目的ファイルが最新のままである。コンパイラ、
リンカ、archiver、別に宣言した assembler（ADR-0050）、transform の
`objcopy`、生成が走らせるプログラム（ADR-0054）のいずれも同じだった。

## 綴り方は既にあった

[ADR-0028](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0028-probe-facts.md)
は `facts::identity`——path・大きさ・mtime——を記録した probe の鍵へ混ぜて
おり、まさに「入れ替えられた道具の答を古い記録から返さない」ためである。
**その同一性が、ビルド自身の鮮度へは渡っていなかった。**

## 辺ではなく file である

運び方は2つありえた。

| 形 | なぜそれでは足りないか |
|---|---|
| plan の辺 | ninja は `deps` を読まない。file の関係でない順序は、既定の backend では順序ですらない（ADR-0054 が測った） |
| **file** | 3つの backend が揃ってやっている唯一のことが、入力と出力を比べることである |

```
<build>/tools/<名前>-<digest>.stamp
```

digest が分けているのは**書かれた綴り**である。`cc` と `/usr/bin/cc` は同じ
ファイルに解決しても別の宣言なので別の板を持ち、中身は等しくなるので板が
それだけで何かを組み直させることはない。中身は **PATH 上で解決した実体**の
同一性であり、名前の同一性ではない。

## 何を確かめるか

| 見るもの | 期待 |
|---|---|
| 板 | 道具ごとに1つ。名前は読めるまま、digest が宣言を分ける |
| 中身 | 解決した実体の path・大きさ・mtime |
| グラフ | `tool_stamps` に現れ、アクションの `inputs` にも現れる。`version` は 2 |
| 入れ替え | 3つの backend すべてで、包みを書き換えれば作ったものを組み直す |
| 入れ替えない | 板の mtime が動かず、何も走らない |
| `check` | 道具を解決するが、何も書かない |

**組み直さないことの対照が要る。** それが無ければ「毎回組み直している」と
区別が付かない。

## 板は中身が変わったときだけ書かれる

書き直せば mtime が動き、mtime が動けばその道具を使う全てが組み直る。
道具が変わったときには正しく、変わっていないときには誤りである。だから
書くのは中身が違うときだけであり、検査はビルドを挟んで mtime が動かない
ことを見る。

## 取りこぼす場合

| 場合 | なぜ |
|---|---|
| 同じ秒に、同じ大きさで入れ替わった道具 | mtime は1秒刻み。ADR-0028 がコンパイラを数十メガバイト読まないために選んだ粒度をそのまま継いでいる |
| 駆動器の裏側だけが変わった場合 | `cc` は駆動器である。同じ `gcc` の下の新しい `cc1` は見えない。見えるようにするには plan の段で毎回コンパイラを起動することになる |
| 同じ中身で入れ直された道具 | mtime が動くので組み直る。mtime を見るビルドシステムがソースに対して持つ偽陽性を、道具へ当てたものである |
