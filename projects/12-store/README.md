# 12-store — プロセスを跨いだ評価結果の復元

`dowel` は常駐しない（[ADR-0002](https://github.com/sabas0ba/dowel/blob/main/docs/adr/0002-no-daemon.md)）。
1回の実行ごとにプロセスが終わるため、**次のプロセスが前回の仕事を引き継げるか
どうか**がそのまま増分の土台になる。引き継ぎはディスク上のストア
（`.dowel/cache/<形式版>/`）が担う。

[05-incremental](../05-incremental/) は同一プロセス内での再ビルドを見る。
ここで見るのはその手前、**プロセスを跨いだ復元**である。

[F-014](../../docs/10-findings.md#f-014) が示したように、記録が引き継がれない
経路は黙って古い結果を返す。だから復元は「速くなったか」ではなく、
**何を引き継いだか**と**引き継げなくても答が変わらないか**で見る。

## 何を固定するか

### 1. 引き継ぎが起きること

`--log-level=debug` に1行出る。

```
store: wrote 2 values, restored 0, skipped 0 with diagnostics
store: wrote 0 values, restored 2, skipped 0 with diagnostics
```

新規の木では書くだけ、次のプロセスでは復元するだけ。数で見る。
時間で見ると、速い機械では差が測定誤差に埋もれる。

### 2. 変更の検出

`--log-level=trace` に判定が出る。

| 判定 | いつ |
|---|---|
| `UnchangedByStat` | `(mtime, size, inode, ctime)` が一致 |
| `UnchangedByContent` | stat は違うが内容の指紋が一致（`touch` しただけ） |
| `Changed` | 内容が違う |

触っただけと書き換えたのを区別できなければ、**触るたびに評価をやり直すか、
書き換えても気づかないか**のどちらかになる。

### 3. 診断を持つファイルは格納しない

格納の対象は、診断を1件も出さずに**評価できた**ファイルに限る。
誤りを含む評価結果を引き継ぐと、直したあとも古い診断が残りうる。

型検査の段の診断（`unknown-property` など）は評価のあとに出るため、
格納は妨げない。ここで見るのは評価段の診断（`unknown-cfg-key`）である。

### 4. 壊れたストアが答を変えないこと

> 形式の版が合わない場合、切り詰められた場合、外部から書き換えられた場合の
> いずれでも、結果は変わらず速度のみを失う

**ストアは速度のための記録であり、答の一部ではない。** 壊れた記録が答を
変えるなら、それは記録ではなく入力である。

8通りを与えて、`check` の出力が1バイトも変わらないことを見る。

| | |
|---|---|
| `values` を切る / 空にする / 消す / 乱数で埋める | 値ログ側 |
| `index` を端数で切る / 消す / 乱数で埋める | インデックス側 |
| 知らない形式版のディレクトリだけがある | 版の不一致 |

あわせて、**壊れたあと自力で作り直せること**も見る。壊れたまま固まるなら、
一度の破損が恒久的に速度を失わせる。

### 5. 掃除

`cache info` が中身を報告し、`cache gc` が古い形式版だけを消して現在の版を
残すこと。

## この形で確かめられないもの

復元による短縮の大きさ。本体の計測では現在のフィクスチャの規模で
0.1〜0.2ms であり、外から安定して測れる差ではない。ここで見るのは
**引き継いだ件数**であって、速度そのものではない。

書き手が1つに制限されること（`flock`）。同時に走らせる検査は書けるが、
どちらが勝つかは競争の結果であり、機械によって変わる
（[docs/00-design.md](../../docs/00-design.md) 6節）。
