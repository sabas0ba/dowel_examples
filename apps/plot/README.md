# plot — GUI

GUI は「走らせて見る」ことができない層だと思われがちである。実際に確かめられ
ないのは**窓が綺麗かどうか**だけで、その手前はすべて機械にかけられる。境目を
どこに引くかが設計であり、それを支えられるかがビルドツールへの問いになる。

```
core/   描画。画素の並びを作るところまで。cairo にだけ依存し、窓を知らない
ui/     見せる側。窓を開く実装とファイルへ書く実装があり、選ばれた側だけ翻訳される
```

```console
$ dowel -C ui build                              # 既定。窓を開かない
$ ./plot --out chart.ppm --size 240x120
$ dowel -C ui build --features=x11               # 窓を開く
$ xvfb-run -a ./plot --size 240x120
plot: drew 240x120 on the display
```

## 3つの高さで確かめる

| 高さ | 確かめ方 | 何が分かるか |
|---|---|---|
| 描画 | `plot_pixel` を直に読む | 背景の隅が厳密に `PLOT_BACKGROUND` であること |
| 書き出し | PPM を読み返す | 見出しの寸法と、本体の長さが画素数に一致すること |
| 窓 | **Xvfb の上で走らせる** | 本物の X の伺服体に繋ぎ、窓を作り、画素を置けること |

一番上は組み込みで qemu を相手にするのと同じ形である。GUI でも、**組んだ
ものを実際に起動する**ところまで行ける。

背景を単色で塗っているのは、比較を厳密にするためである。cairo の版が変われば
線の縁の階調は変わるが、単色塗りの画素は変わらない。「だいたい合っている」で
はなく「この値である」と書ける形を選ぶ。

## 任意の依存

窓を開く構成だけが X11 を要る。要らない構成の成果物に X11 が残っていたら、
それは配布先の前提を1つ増やしたということである。

```console
$ readelf -d plot | grep NEEDED      # 既定の構成
libcairo.so.2
libc.so.6

$ readelf -d plot | grep NEEDED      # --features=x11
libcairo.so.2
libX11.so.6
libc.so.6
```

`optional = true` の依存は、機能が立っていなければ**計画にすら現れない**。
引数から消えるだけではなく、パッケージが読み込まれない。`expect.sh` は
リンクの引数と `NEEDED` の両方で見ている。

表示が無い機械で実際に走らせるところまで確かめている。前提が本当に減って
いるかどうかは、`NEEDED` を読むより走らせる方が確かである。

## 関門: 排他な機能（[F-031](../../docs/10-findings.md#f-031)、`17bd54e` で開いた）

見せ方は択一である。機能は加算なので、`--features=x11` は既定の `headless`
を落とさない。両方立った木は組み上がってはならない——それをマニフェストに
書ける。

```toml
[features]
exclusive = [["headless", "x11"]]     # この2つは同時に立てない
```

両方立てると `conflicting-features` で拒まれ、診断が **`default` から来た側**
を名指しする。両方立つ原因はほぼ常にそれであり、`--no-default-features` が
落とし方だからである。

宣言する場所が無かった頃、結果は目標の種別で分かれていた。`bin` に直に
並べればリンカの `multiple definition`（dowel からは何も出ない）、`lib` に
入れれば**組み上がって**、片方が黙って死んだ翻訳単位になった
（[httpd](../httpd/) がその側を固定している）。危ないのは後者である。
組み上がり、テストも通り、成果物だけが頼んだのと違うものになる。

ソースの選択そのものは `match` で書いてある。`when` を2つ並べる形は排他に
ならないためで、`exclusive` はその上に掛かるもう1枚の保険である。

## 何を dowel に効かせているか

| | |
|---|---|
| システムの依存 | cairo と X11 を pkg-config 経由で。解決は `dowel.lock` に残る |
| 公開と非公開 | cairo は private な依存。使う側に見出しは渡らないが、リンクの閉包には乗る |
| 任意の依存 | `optional = true` と同名の機能。立っていなければ計画に現れない |
| 条件つきのソース | `match feature.x11`。選ばれなかった翻訳単位は落ちる |
| 構成が成果物に届くこと | `--shell` が名乗る値が構成ごとに変わる |
| 実行時の安全 | 描画は境界の計算だらけである。計装して 12 通りの canvas を描く |
| 増分 | 描画を触って、隣の翻訳単位が組み直されないこと |

なお、`sanitize` は `plot-core/sanitize` へ転送している。転送した機能名の
`/` がビルドディレクトリを割る件（[F-023](../../docs/10-findings.md#f-023)）は
`17bd54e` で直り、識別子は `plot-core--sanitize` のように1階層へ畳まれる。
